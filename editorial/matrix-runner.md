# Matrix cloud writer

`daily.yml` keeps the existing Node 24, free Ubuntu runner, OIDC identity and publishing concurrency group. Its `7,37 * * * *` checks call `scripts/matrix-daily.mjs publish`; the separate 21:00 UTC development-comment schedule remains. The old 18:00 UTC article cron is removed. Manual `audit` is the default and never calls a model or deploys.

The Matrix plan supplies the selected skill instructions/resources and question-bank snapshot. Only two pending unpublished questions are reserved per Shanghai day, with at least ten minutes between actual article model starts. Paused/not-due plans make no paid calls. Successful local slots and Matrix recent reports prevent duplicates. New calls use only `qwen-plus` at validated `DASHSCOPE_BASE_URL`; there is no model fallback.

Each article uses bounded research, writing and source-based review calls. Primary pages must be opened and their text/hash retained; every public field is reviewed, factual citations require matching original-source quotations. Only approved artifacts enter the production build. Hosting-only deployment is verified against each public page's SHA256 before a published report and Matrix search submission. A search rejection is a search receipt, not a publication failure. Firestore data/rules are not deployed by this runner.

Existing encrypted history/cache remain in `automation-state/runtime.enc.json`. New reservations, inputs, responses, immutable usage events, original snapshots and report outbox use `state.matrixRuns` and namespaced call rows. A pending/ambiguous request is retained for inspection and never blindly retried. Repeated report delivery does not regenerate content. Known token prices are estimates, missing usage remains unknown, and unconfirmed search charges are excluded from token estimates and explicitly noted.

Matrix must accept the research/writing/review stage report before the next paid step, and accept the completed review report before publication. An unconfirmed report stops the batch with the exact encrypted outbox and successful caches retained; transient recovery replays the report before resuming. HTTP 4xx rejections retain an inspection marker. Ambiguous provider requests stop the second article and remain blocked across calendar days. Article writes compare the original reserved file hash, protecting concurrent edits even when they retain the same plan metadata. Audits count Matrix-managed publication only when the successful encrypted slot and stored page hash agree with a fresh public HTTP200/hash check; source-only approved artifacts are reported separately.

Required Actions secrets: existing `DASHSCOPE_API_KEY`, `DASHSCOPE_BASE_URL`, `BCJ_LEDGER_KEY`, plus `MATRIX_RUNNER_TOKEN` and `MATRIX_SITE_ID`. Matrix defaults to `https://matrix.relaxbrohk.com`. Tokens never enter child process environments or output. No Firebase billing upgrade, paid runner or new service account is needed.

An authentication/model-permission rejection blocks subsequent paid calls in `state.matrixRuns.providerBlocked`; fixing the provider alone does not clear that evidence. Manual publish mode with `recheck_provider=true` authorizes exactly one retry of a known same-day HTTP 401/403/404 rejection, preserving the old receipt and successful stages. That article's total call cap becomes four instead of three. Pending/transport-ambiguous calls cannot use this reset; audit and scheduled checks never enable it. Failed or ambiguous requests retain their original usage uncertainty and are not automatically rewritten. Historical date-only publication values stay date-only in audit metadata.
