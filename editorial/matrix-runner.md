# Matrix cloud writer

`daily.yml` keeps the existing Node 24, free Ubuntu runner, OIDC identity and publishing concurrency group. Its `7,37 * * * *` checks call `scripts/matrix-daily.mjs publish`; the separate 21:00 UTC development-comment schedule remains. The old 18:00 UTC article cron is removed. Manual `audit` is the default and never calls a model or deploys.

The Matrix plan supplies the selected skill instructions/resources and question-bank snapshot. Only two pending unpublished questions are reserved per Shanghai day, with at least ten minutes between actual article model starts. Paused/not-due plans make no paid calls. Successful local slots and Matrix recent reports prevent duplicates. The primary route uses the GEO shared DashScope key and `qwen-plus` at validated `DASHSCOPE_BASE_URL`. The explicitly authorized fallback uses a dedicated Matrix Beauty backup credential under the existing GEO OpenRouter account, hard-pinned `OPENROUTER_MODEL=qwen/qwen-plus`, and only `https://openrouter.ai/api/v1/chat/completions`. OpenRouter requires JSON response format and parameter support; research additionally uses the Exa web plugin with at most six results. Returned citation annotations supplement discovery clues; original pages still must be opened and checked independently.

Each article uses bounded research, writing and source-based review calls. Primary pages must be opened and their text/hash retained; every public field is reviewed, factual citations require matching original-source quotations. Only approved artifacts enter the production build. Hosting-only deployment is verified against each public page's SHA256 before a published report and Matrix search submission. A search rejection is a search receipt, not a publication failure. Firestore data/rules are not deployed by this runner.

Existing encrypted history/cache remain in `automation-state/runtime.enc.json`. New reservations, inputs, responses, immutable usage events, original snapshots and report outbox use `state.matrixRuns` and namespaced call rows. A pending/ambiguous request is retained for inspection and never blindly retried. Repeated report delivery does not regenerate content. Known DashScope token prices are estimates, missing usage remains unknown, and unconfirmed search charges are excluded from token estimates and explicitly noted. OpenRouter `usage.cost` is actual USD reported by the response. An explicit dated CNY-per-USD reference rate may produce estimated CNY; the ledger retains original USD, rate, date and source, and the event note identifies the conversion. Without a verified rate, report actual USD. Missing cost is unknown, never zero. New events distinguish GEO shared DashScope and OpenRouter accounts; historical rows/events keep their existing identities and amounts.

Matrix must accept the research/writing/review stage report before the next paid step, accept a report containing the primary rejection before any fallback, and accept the completed review report before publication. An unconfirmed report stops the batch with the exact encrypted outbox and successful caches retained; transient recovery replays the report before resuming. Only a known HTTP 401/402/403/404/429/5xx rejection with no completion permits fallback. Transport loss, pending requests, malformed successful responses, truncated responses, and HTTP errors containing a completion stop the batch and remain blocked across calendar days. Each stage gets at most one attempt per route; each article gets at most six new calls, with research/write/review output caps of 2000/4300/4200 tokens. Successful stage caches are independent of route/key changes, and replay never purchases another result. Article writes compare the original reserved file hash, protecting concurrent edits even when they retain the same plan metadata. Audits count Matrix-managed publication only when the successful encrypted slot and stored page hash agree with a fresh public HTTP200/hash check; source-only approved artifacts are reported separately.

Required Actions secrets: GEO shared `DASHSCOPE_API_KEY`, validated `DASHSCOPE_BASE_URL`, `OPENROUTER_API_KEY`, `BCJ_LEDGER_KEY`, plus `MATRIX_RUNNER_TOKEN` and `MATRIX_SITE_ID`. The workflow explicitly sets `OPENROUTER_MODEL=qwen/qwen-plus` and `MATRIX_PROVIDER_REVISION=geo-shared-openrouter-v1`. An absent key or unapproved model disables fallback. Matrix defaults to `https://matrix.relaxbrohk.com`. Tokens never enter child process environments or output. No Firebase billing upgrade, paid runner or new service account is needed.

An authentication/model-permission rejection blocks the primary route in `state.matrixRuns.providerBlocked`; subsequent stages use authorized OpenRouter without repeating the rejected primary. OpenRouter permission failures similarly retain their own route block. Failed or ambiguous requests retain their original usage uncertainty and are not automatically rewritten. Historical date-only publication values stay date-only in audit metadata.
